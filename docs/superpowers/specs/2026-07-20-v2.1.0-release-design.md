# v2.1.0 Release

## Scope

Publish the current feature set as release `v2.1.0` and keep every visible
version reference aligned.

## Version Sources

- Set `manifest.json` to `2.1.0`; Chrome uses this as the extension version.
- Set `package.json` to `2.1.0`; this keeps development metadata aligned.
- Update the README version badge and add a `v2.1.0` changelog entry.

## Release Process

1. Run the existing test and lint commands.
2. Commit the version and README updates.
3. Push `main` to GitHub.
4. Create and push annotated Git tag `v2.1.0`.
5. Create a GitHub Release for `v2.1.0` with notes summarizing the current UI
   and tab-collection improvements.

## Error Handling

- Do not create the tag or GitHub Release if tests or lint fail.
- Do not proceed if the repository has unrelated uncommitted changes.
